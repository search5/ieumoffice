# 0118 — AI가 WebDAV 서버를 둘러보고 읽는다 (읽기만, 기본 꺼짐)

## 맥락

결정 0117은 WebDAV 열기·저장만 넣고 AI 읽기를 "나중에"로 남겼다. 사용자가 AI 읽기를 요청했다(2026-11-09). 정해야 했던 것은 0117이 적어 둔 네 가지였다.

Drive와 다른 점:

- Drive는 Google 선택 창에서 고른 파일만 AI가 본다. WebDAV에는 선택 창이 없다. 서버가 보여 주는 폴더 전체를 AI가 걸을 수 있다. 노출 범위가 훨씬 넓다.
- 서버에는 이름 말고 본문을 찾는 표준 방법이 없다(DASL은 거의 구현되지 않는다). 검색은 파일 이름 찾기가 된다.
- Google Workspace 정책은 걸리지 않는다.

## 결정

**스위치는 기본 꺼짐.** 설정 → 연동의 "AI가 WebDAV 서버의 파일을 찾아 읽기"(`app-settings.json`의 `webdavAiAccess`)를 사람이 켜야 한다. Drive는 연결하면 켜지지만(고른 파일만 보이므로), WebDAV는 서버 전체가 보이므로 사람이 한 번 켠다. 서버별 스위치는 두지 않았다: 켜는 순간 연결한 서버 모두에 해당한다. 서버를 따로 막고 싶으면 그 서버를 지운다.

**도구 셋.** `webdav_list`(서버 목록 / 폴더 안 목록), `webdav_search`(파일 이름), `webdav_read`(본문, 2만 4천 자씩). 모두 읽기뿐이다. 파일은 `서버 id + 연결한 폴더 기준 경로`로 가리킨다. 모델이 서버 이름을 줘도 하나로 정해지면 받는다.

**검색.** 서버에 본문 검색이 없으므로 시작 폴더에서 너비 우선으로 `PROPFIND`(Depth 1)를 걷는다. 한도: 4단계, 폴더 80개, 항목 5,000개, 25초, 동시 4개, 숨김 폴더 건너뜀. 한도에 닿으면 `incomplete`를 돌려주고, 모델은 서버와 폴더를 좁혀 다시 찾도록 안내받는다. 모든 단어가 이름에 들어 있는 파일만 맞는다.

**읽기.** Drive와 같다. 임시 폴더에 받아 `parseFileToText`로 읽고 지운다(가리기 적용, 결정 0016). 열 수 있는 형식(`OPENABLE_EXTENSIONS`)만 읽는다. 읽은 글은 10분, 4개까지 메모리에 두고, ETag·수정 시각·크기가 같을 때만 다시 쓴다.

**바깥으로 내보내는 길 막기.** `webdav_read`가 성공하면 그 대화에서 `OUTBOUND_TOOLS`와 주소를 가져오는 호출을 거절한다(결정 0033과 같은 규칙, `guardWebDavContent`). 저장된 대화를 다시 열면 기록에서 다시 판단한다.

**무료 연결 거절.** 세 도구 모두 무료 연결(`isFreeAi`)이면 거절한다. Google 정책 때문은 아니고, 학습을 끌 수 없는 연결에 사용자의 서버 내용을 넘기지 않는다는 Drive와 같은 선이다.

**학습 설정 확인 체크는 두지 않았다.** Drive의 `driveTrainingAck`는 Google 정책이 요구해서 생겼다. WebDAV는 정책이 요구하지 않고, 스위치가 이미 기본 꺼짐이라 켜는 순간이 동의다. 설명 문구에 "읽은 내용은 쓰고 있는 AI 제공자에게 간다"를 적었다. 나중에 확인을 요구하기로 하면 스위치 앞에 체크를 더하면 된다.

**WebDAV 사본 탭의 AI 요청 거절은 넣지 않았다.** Drive는 사본을 연 탭에서 무료 AI 요청을 거절한다(`setAiRunGuard`, 한 자리뿐인 훅). WebDAV 사본은 PC 파일처럼 열려 있는 문서이고, 사용자가 직접 고른 AI로 보내는 것은 다른 PC 파일과 같다. 훅을 두 서비스가 나눠 써야 해서 Drive 코드를 건드리게 되는 것도 이유다.

**연결 방식.** 별도 채널을 편집기마다 만들지 않았다. 편집기 preload가 이미 `window.aiOfficeDriveAi`(`driveAiBridge()`)를 내주므로 그 다리에 `webdav*` 호출을 더했고, `composeWithDrive`가 같은 자리에서 WebDAV 스킬을 엮는다. 편집기 10곳의 preload는 고치지 않았다.

## 택하지 않은 것

- **서버별 AI 스위치.** 화면과 상태가 늘고, 서버를 지우면 같은 효과다.
- **본문 검색(서버가 지원하는 경우).** 서버마다 달라 앱이 맡기 어렵다. 이름 검색과 `webdav_read`로 AI가 후보를 읽어 가린다.
- **AI가 쓰기(저장·새 파일).** 0033의 읽기 전용 원칙을 이어 간다. 쓰기는 사람이 누른 저장뿐이다.
- **서버의 폴더를 미리 색인해 본문을 검색한다.** 서버 전체를 PC에 복제하게 된다.

## 결과

- 사용자가 스위치를 켜면 "서버에서 지난달 회의록 찾아서 요약해 줘"가 된다.
- 새 전송 경로: 앱 ↔ 사용자의 서버(목록, 내려받기)는 0117과 같다. 서버 내용 → AI 제공자가 새로 생긴다. `PRIVACY.md`에 적었다.
- 남은 것: 실제 서버로 AI 검색·읽기 사람 확인(느린 NAS에서 25초 한도가 맞는지), 도움말 주제.
